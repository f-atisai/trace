# Guides

Task-oriented guidance for using TRACE in statistical-programming workflows.

Start here if you understand what TRACE is and want to use it in a program:

1. [`getting-started.md`](getting-started.md) — install TRACE, instrument a statistical workflow, read live events, and review a finalized provenance-backed log.
2. [`../../examples/README.md`](../../examples/README.md) — run the public CDISC Pilot Study flagship programs.
3. [`../examples/README.md`](../examples/README.md) — interpret those programs from a reviewer perspective.
4. [`quarto.md`](quarto.md) — use TRACE inside Quarto while keeping TRACE independent of the authoring environment.

Reference material:

- [`../api/README.md`](../api/README.md) — authoritative Developer Preview Python API.
- [`../framework/core-operations-v0.1.md`](../framework/core-operations-v0.1.md) — canonical TRACE operation meanings.
- [`../framework/reviewer-guide.md`](../framework/reviewer-guide.md) — reviewer workflow for TRACE execution evidence.

The design documents explain rationale and architecture history; they are not required to use TRACE.
